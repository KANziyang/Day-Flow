# DayFlow 架构

## 数据流

React → 类型化 Service → Tauri IPC → Rust Repository → 单例 SQLite Connection。

两个 WebView 共享 Rust 管理的一个 `Database`。连接由 Mutex 串行化，WAL、外键、5 秒 busy timeout 与 FULL 同步模式开启。数据库存放在 Tauri 的 `app_data_dir/com.dayflow.desktop` 对应目录（Windows 通常为 `%APPDATA%\com.dayflow.desktop\dayflow.db`，以设置页显示为准）。

写入提交成功后广播 `data-changed`，两窗口刷新快照；焦点恢复时再次读取。无逐秒数据库轮询。30 秒的本地时钟更新只重新计算 UI 到期状态。后台提醒每 30 秒检查一次。

## 持久化与历史

`PRAGMA user_version` 管理按版本逐步执行的 SQL 迁移；已执行的迁移不得修改。当前版本为 3，第三次迁移从偏好 JSON 中删除 `widget_mode`，其他偏好和窗口位置原样保留。第二次迁移为手动记录增加必填 `kind`（`completed | progress`），旧日志统一成为 `progress` 并保留原文。任务与事件使用同一个事务。状态重复写入是幂等操作；任务和手动记录表单更新带 `expected_updated_at`，拒绝覆盖另一窗口的新版本。设置只修改指定键，避免用旧快照覆盖其他设置。

事件快照包含任务当时的全部字段以及分类名称。后端提供 `WorkRecord` 来源联合类型：`TaskCompletion` 包含完成事件、任务 ID、本地所属日期、标题快照、完成时间及后续重开时间；`Manual` 包含手动记录。快照统一返回 `work_records`，首页、工作记录页与报表使用同一投影，不额外为完成任务创建手动日志。

日记录按任务 ID 与本地完成日期去重，保留当天最后一次完成快照；列表按所属日期、完成或手动创建时间倒序。手动关联只表示关联，既不改变任务状态，也不与自动记录合并。重开标识来自完成之后转为待办或进行中的状态事件，不能仅依赖旧版 `reopened` 事件名，因为旧数据中的取消事件也可能使用该名称。

报告读取事件 UTC 时间，使用查询时本机时区分别计算每个日历边界，不以固定 24 小时推算日/月/周，也不使用截止日期推断完成日期。`Report` 只返回本周期与下一周期的包含终日范围、统一工作记录、全部期末未完成任务及其中截止日期落入下一周期的任务；下一周期按同一种日历周期计算。报表完成清单按周期内任务 ID 去重、采用最后一次快照；原始完成事件完整保留。未完成范围包含期末所有未删除的待办和进行中任务，不按截止日期过滤，因此和下一周期任务允许重复。

SQLite 在线 Backup API 用于手动与每日启动备份。恢复流程：只读打开版本 1、2 或 3 的源备份 → 复制到临时数据库 → 执行当前迁移 → integrity_check、表结构、外键、数据与快照反序列化检查 → 原库安全备份 → 在线 Backup 替换 → 广播刷新。源备份保持原样，迁移或验证失败不替换当前数据库。替换期间持有数据库锁，防止并发写入。JSON 导出格式为版本 3，包含统一工作记录和完整原始事件，设置中不再包含窗口模式。

## 原生窗口

`windows/mod.rs` 通过 Tauri 显示、隐藏窗口及恢复物理位置，恢复时检查当前监视器并修正不可见位置。小组件在 `tauri.conf.json` 中固定 `alwaysOnTop: true`，由框架创建为独立置顶窗口；显示、隐藏、备份恢复及重启均不切换窗口模式。

桌面宿主模块及其 Win32 依赖、模式 IPC、运行时模式状态、Explorer 宿主检查和退出解除挂载逻辑均已移除。退出时保存窗口几何信息，由 Tauri 完成窗口销毁。

## 前端

严格 TypeScript，React Hooks 与 Context 管理本地快照。任务排序、报表文本格式化在 Service；视图负责筛选和交互。CSS 使用系统字体与 Lucide 图标，无远程字体、CDN、网络数据请求。浏览器直接访问开发地址会明确告知需要 Tauri，不提供伪装成数据库的 localStorage 副本。
