# DayFlow V1.0.1

Windows 10/11 本地任务、工作记录与周期复盘应用。Tauri 2 + Rust + React 19 + TypeScript + SQLite。核心数据留在本机，运行不依赖网络、账号或 AI 服务，首次启动不写入示例任务。

## 安装与日常启动（Windows 11）

安装包为 `src-tauri/target/release/bundle/nsis/DayFlow_1.0.1_x64-setup.exe`。双击后按简体中文安装向导完成安装；使用 Tauri 2 官方 NSIS 安装器，安装到当前用户，无需每次运行源代码。

默认程序位置为 `%LOCALAPPDATA%\DayFlow\dayflow.exe`。安装后从开始菜单的 **DayFlow** 或桌面快捷方式启动，任务与工作记录保存在独立的应用数据目录。日常使用不需要 Node.js、Rust、命令行或开发服务器。

可在 Windows“设置 → 应用 → 安装的应用”中卸载 DayFlow。卸载器默认保留本地数据；只有明确选择删除应用数据时才会删除数据库与备份。重新安装可继续使用保留的数据。

安装器尚未代码签名。WebView2 是运行所需组件；Windows 11 通常已经安装，缺少时安装器会下载该组件。

### 安装新版本

先在 DayFlow 中选择“退出应用”（仅关闭主窗口默认仍在后台运行），再双击新版安装包。安装器识别已有版本；升级页面可选择“请勿卸载”继续安装到原目录，覆盖程序文件，也可选择“安装前卸载”。任务、工作记录和设置位于独立的数据目录；不要选择卸载器中的“删除应用数据”，即可保留记录。

主窗口左侧底部与设置页底部显示当前版本 `V1.0.1`，由 Tauri 构建配置统一提供。应用暂未接入联网自动检查更新，更新方式是手动安装新版 EXE。

## 开发启动

开发需要 Node.js 20、Rust MSVC 工具链、Visual Studio C++ 桌面开发工具和 WebView2。本次使用 Node.js 20.18.2、Rust 1.99.1、React 19.3.1、Tauri Rust/API 2.12.4、CLI 2.12.3、Vite 6.4.4。

```powershell
cd C:\Users\hp\Desktop\DayFlow
npm install
npm run tauri dev
```

本项目 `.tools` 若存在本次安装的 Rust 工具链，包装脚本会自动使用；其他电脑使用正常安装并位于 PATH 的 Rust。`.tools` 不属于交付源代码，不进入安装包。`npm run dev` 只是浏览器服务，不能当作完整应用启动方式。

参考 [Tauri 官方 Windows 环境要求](https://v2.tauri.app/start/prerequisites/)。首次安装时如果系统缺少 WebView2，默认安装器会下载该组件。已具备 WebView2 后，任务、日志和报表支持离线运行。

## 使用

- 小组件输入标题并按 Enter 创建任务；主窗口与小组件的所有新建入口默认截止日期为今天、时刻留空，可修改或清空日期。日历按钮设置日期与可选时刻；左侧圆圈完成，点击标题打开详情。
- 任务详情明确保存，支持描述、四种状态、三档重要程度、分类、截止日期/时刻。删除进入回收站，可恢复；完成、重开和删除事件保留。
- 今日待办管理待推进任务；完成任务自动进入实际完成当天的工作记录，保留完成时的标题。重开、改名和移入回收站不会抹掉历史成果。
- “工作记录”默认查看今天，统一展示“任务完成”“手动完成”和“工作进展”。临时完成事项无需先建任务，手动新建默认为“已完成事项”，也可切换为“工作进展”、补录历史日期和关联任务；关联不改变任务状态，也不合并自动记录。
- 周期复盘支持历史日报、周报、月报和复制总结，统一只包含实际完成事项、工作进展、下一周期需要完成的任务、未完成的任务。“实际完成事项”分别标明任务和手动来源；下一周期分别为明天、下周一至周日、下一个自然月。
- Ctrl+N 聚焦快速添加，Ctrl+K 搜索，Escape 关闭详情，未保存先确认。

## 窗口与退出

主窗口默认 1120×760，小组件 320×420，最小 260×300。小组件顶部拖动、边缘缩放。默认关闭主窗口后隐藏，后台与小组件继续运行；可在设置修改。主窗口左下角和系统托盘提供彻底退出入口。应用使用单实例插件。

置顶使用 Tauri 原生 always-on-top。桌面模式先由独立 Win32 模块查找包含 `SHELLDLL_DefView` 的桌面图标宿主并检查 DPI 上下文；小组件与图标视图同级，位于图标之上，不使用图标后面的壁纸 WorkerW。只有实际 SetParent 成功才显示桌面宿主。失败准确显示“桌面兼容模式”及原因，实际行为是普通非置顶窗口。模式保存并在重启恢复。**普通非置顶不等于真正桌面嵌入。**

挂载后通过原生接口显示和隐藏，避免窗口框架改写子窗口样式。切换模式时保留当前位置和可见状态；真正退出时先隐藏、解除桌面挂载，再完成框架清理。

位置以物理坐标保存，拖动停止后合并写入，正常退出时再次保存；启动检查监视器并纠正不可见位置。真正桌面挂载的 Explorer 重启、混合 DPI 和多显示器行为需逐设备验收，见 [测试记录](docs/TESTING.md)。

## 数据与备份

实际数据目录在设置页显示，Windows 通常为：

```text
%APPDATA%\com.dayflow.desktop\
  dayflow.db
  dayflow.db-wal
  dayflow.db-shm
  backups\
  exports\
```

只使用一份 SQLite，由 Rust 单例连接管理。开启 WAL、外键和 FULL 同步；重要操作包含事务，表单校验版本以避免覆盖另一窗口修改。

- 每天首次启动自动创建一致性备份，也可手动备份；保存在 `backups/`，不会自动删除。
- JSON 导出格式为版本 2，保存在 `exports/`，包含任务、统一工作记录、分类、设置和完整历史事件。当前恢复只接受本应用 SQLite `.db` 备份。
- 数据库迁移版本为 2；旧版手动日志保留原文并归为“工作进展”，可在工作记录中修改类型。
- 恢复支持版本 1 和 2 的备份：只读打开源文件，复制到临时数据库、迁移并检查完整性、表结构、外键与事件快照；验证后先保存 `before-restore-*` 原数据备份，再替换数据库。源备份不被迁移或修改。
- 运行中不要单独复制 `dayflow.db` 作为备份，使用内置在线备份以包含 WAL 中的已提交数据。

工作记录由完成历史和手动记录共同生成，自动完成不额外写入手动记录。自动记录只读，保留完成时的标题；之后转为待办或进行中，标注“之后重新开启过”，取消不算重开。同一任务同一天多次完成，日记录采用当天最后一次快照，不同日期分别保留。日内按完成时间或手动录入时间倒序，先按所属日期倒序分组，补记按选择的所属日期归档。

报表的完成任务按周期内任务 ID 去重并采用最后一次完成快照，原始完成事件完整保留。未完成的任务依据周期结束时的状态，包含逾期、未来到期及无截止日期的全部待办和进行中任务；下一周期任务是其中截止日期落入下一周期的子集，会同时出现在两个栏目中。任务显示截止日期和可选时刻，无日期时明确标注。日历边界分别换算到 UTC，正确处理夏令时，避免假设每天固定 24 小时。工作记录页继续分别展示完成任务数、手动完成事项数和工作进展数。

具体截止时刻以录入时确定的 UTC 瞬间保存，界面保留录入的本地日期/时刻。仅修改描述或分类不会因系统时区变化而重算截止；明确修改日期/时刻时，才按当时本地时区重新确定。仅日期任务按所在本地日历日判断。

## 当前边界与已知问题

- 原生桌面宿主依赖 Explorer 非公开结构，设有可用性和 DPI 检查。兼容模式是普通窗口行为，不能视为全部原生桌面验收通过。
- 已有宿主失效检查，但真正挂载时 Explorer 重启造成的子窗口销毁/恢复仍需专项验收，不承诺已完全解决。
- V1.0.0 的 Windows 11 安装/卸载已实测；V1.0.1 的设备回归，以及多显示器热插拔、不同 DPI、通知投递、开机登录启动仍需继续验收。
- 通知默认关闭，每个截止时间只提醒一次，支持勿扰；仅日期任务默认 09:00 提醒。显示还受 Windows 权限和专注助手影响，开发与正式安装表现可能不同。
- 手动记录删除永久生效且需要确认；任务软删除。手动记录被编辑、调整日期或删除后，报告随数据库变化；自动完成记录由任务历史生成，不能直接编辑或删除。
- 没有云同步、账号、AI 总结、重复任务、自动更新、Markdown 文件导出，不显示这些能力的占位开关。
